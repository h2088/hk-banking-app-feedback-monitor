# 执行与阶段判断

## A：来源和范围

以用户当前明确范围为准。默认配置在 `assets/apps.json`，不要根据相似名称猜包名或 Apple ID。新对象先核对官方商店名称、发行者、ID、地区；Apple lookup 可核对数值 ID，Google listing 快照需要执行者查看标题／发行者是否符合任务。脚本不是发行者身份认证工具。

`init` 只写配置和本批计划，不代表采集成功。`collect` 完成后才写实时采集模式的 A；`import` 的 A 明确为历史快照。公开页面可访问、语言请求参数、香港 storefront 均不能证明全量覆盖或作者居住地。

## B：采集和输入冻结

Google 使用公开 `batchexecute` 评论 RPC（`oCPfdb`），按最新排序，单页请求 200 条，跟随 continuation token。停止条件为无 token、token 重复／没有新 ID、连续两页完全早于窗口，或配置页数上限。`all_history=true` 只取消早于窗口的停止条件，仍不是“全历史完整性”保证。

Apple 使用香港公开 RSS，`sortBy=mostRecent`。默认每应用页 1–10；依次尝试带语言 JSON、无语言 JSON、Atom XML。中途空页要保存并继续后续页，不能直接把空页解释成结束；遇重复 ID 无新增则停止。若第 10 页有评论，会观察第 11 页边界并记录返回数量，但不把它自动混入已声明的 1–10 页样本。历史原项目每应用拿到 500 条是当时结果，不是端点承诺。

每次 HTTP 响应保存 `.body` 与 `.http.json`，后者含 URL、方法、请求体、响应状态、采集时间和 SHA-256。Google 另存 decoded JSON。HTTP 超时 35 秒；暂时性失败最多 3 次，等待 2、4 秒；401／403／404／429 直接停止。TLS 保持验证。

整个采集如失败，保存失败状态及已写入各来源的 `rows_partial.json`，不继续冒充完整四源批次，也不生成成功的 `source_records.json`。先检查原因；重试用新目录。若用户希望只分析部分来源，要明确来源缺口并将可用记录作为声明了覆盖限制的导入批次。不要静默重复调用同一失败批次。

导入仅接受已映射到本 Skill 字段的 JSON 数组，原始证据必须可访问。复制引用的 raw 和 decoded 文件，以内容哈希命名，保留原路径与原行号；不重新识别语言、不伪造采集时间。只有 CSV 或原始响应缺失时，可先帮助映射／补证据，不能把无法追溯的文件标记为本流程全通过。

## C：合并和 QA

`prepare` 生成四种集合：已取回全部记录、截止日前全部英文、窗口内全部语言、窗口内英文；所有集合按 Unix 时间降序、同秒按唯一键排序。沿用历史文件名 `six_months`，但真实窗口始终读 config／manifest，用户可指定不同长度。

唯一身份键重复会停止处理，要求检查冲突；相同内容而 ID 不同保留并打质量标签。采集分页时遇到相同 ID 只保留首次，记录重复数量和原始页面；若担心期间编辑，需要额外比较 raw 版本，而不是推断同 ID 从未变更。QA 保留来源、应用、月份、星级覆盖表，最终 HTML 按应用汇总。

语言修订只在 `prepare` 前编辑 config，精确文本保护防止误套。`prepare` 后配置冻结，改口径时创建新批次。QA 校验语言状态字段，不等于独立语言准确性验证。

## D：分析和阅读检查

先读 [methods.md](methods.md)。`analyze` 生成逐条标签、总体指标、每应用主题、月度计数／低星比例、示例评论、检查样本，抽查记录初始为 pending。

按每应用 × 每个有数据的星级选择最新一条，最多 10 条。执行者实际阅读标题、正文和标签，记录匹配或不一致、短文本限制。发现实质错误时判断影响：若需要改规则，更新代码并用新批次重算；轻度宽泛匹配可以保留可审计规则输出，同时记录并在解释中披露限制。不能为了对齐旧指标而回避错误。

## E：报告和验证

`build` 需要完成抽查记录；生成单文件 HTML 和构建清单。离线核心不发外部请求。60 条一页，应用、星级、星级情绪、主题、关键词可组合，所有记录都能翻到。来源链接联网，raw、CSV 等证据链接使用相对路径。

`verify` 独立重算展示指标，校验输入、CSV、Excel 结构、原文、主题分母、月度与哈希。它不独立验证主题语义，也不证明网页当前仍有同一评论。`browser-test` 使用已安装 Chromium 系浏览器、全新 headless profile，对临时副本注入交互断言，不修改交付 HTML。检查三张截图；主题／评论截图隐藏其他区段用于聚焦，不是整页原始截屏。无浏览器或执行受限时，报告具体未验证内容，不能手写通过结果。

## F：交付

截图和重要结论经阅读后运行 `finalize`，它再次验证静态结果、抽查状态和浏览器 HTML 哈希，输出 E、F、handover、final_manifest。脚本无法证明业务验收、原始数据真实性或截图已被人看过，因此执行者仍需基于实际工作表述完成范围。

已有批次只继续缺失阶段；检查输入和配置哈希后再继续。已存在的采集、合并、QA、分析、报告和最终文档会拒绝覆盖；测试结果允许重跑。完成后只读复核，不自动重新采集。原始项目的 A–F 文档由执行者修订得更详细，新批次生成文档是参数化起点，可根据真实情况补充解释。
