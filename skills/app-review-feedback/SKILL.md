# 应用评论监测与竞品对比

把公开应用商店评论转换为可核查的总体对比报告。默认对象为 SC Mobile Hong Kong，对照为 HSBC HK Mobile Banking；Google Play 与 Apple 合并后按应用报告。默认窗口为本轮香港日期往前六个日历月，含起止日期。所有脚本路径相对于本 Skill，运行输出写入用户项目的新批次目录。

## 先识别本轮任务

先查看已有配置、计划、checkpoint 和文件清单，判断用户要求的是新采集、已有快照分析、继续未完成批次，还是只解释／复核。只解释或复核时不重新采集、构建或修改用户结果。用户指定的对象、窗口和输出位置优先；已明确的信息不再重复询问。

当前引擎支持香港、英文、两款应用（一主对象一 benchmark）、跨商店总体报告。应用 ID 和名称可通过配置替换；11 类主题针对银行业务。其他行业、地区、语言或多对象分析需要先适配方法和脚本，不能只改配置后宣称已支持。

- 执行项目时，阅读 [workflow.md](references/workflow.md) 和 [execution.md](references/execution.md)。
- 清洗、导入、解释情绪／主题、填写抽查记录或调整规则时，阅读 [methods.md](references/methods.md)。
- 需要了解原项目的历史结果、代码来源或维护测试时，阅读 [validation.md](references/validation.md)；历史数量不能作为新批次的默认结果。

## 工作流

用 `scripts/run_feedback.py` 执行独立阶段，阶段之间检查实际输出和错误，再运行下一阶段。

| Checkpoint | 工作与产物 |
|---|---|
| A | 识别应用、窗口和公开来源；采集模式保存实时来源响应，导入模式明确未做实时验证 |
| B | 有界分页采集或导入快照，保留原始响应、参数、时间、停止原因；生成新到老的合并 JSON／CSV／XLSX |
| C | 校验身份、时间、语言标签、重复、缺失、证据文件和来源构成；不因重复措辞或正文短而删评论 |
| D | 星级映射情绪、补充文本词典、11 类多标签主题、总体与月度比较；实际阅读分层样本并记录判断 |
| E | 构建离线 HTML，验证数字、原文、来源、筛选、翻页和空状态，检查截图 |
| F | 确认抽查记录、测试与同一 HTML 哈希匹配，生成交接和完整性清单 |

CLI 顺序：`init` → `collect` 或 `import` → `prepare` → `qa` → `analyze` → 阅读并填写 `manual_review.json` → `review-status` → `build` → `verify` → `browser-test` → 检查截图 → `finalize`。

## 必须保留的方法边界

1. `text` 是客户评论正文；Apple `title` 独立保留，作为规则匹配、展示、检索的补充。开发者回复不进入客户评论分析。保持原文、ID、星级和时间，不改写成“更通顺”的评论。
2. 请求 `hl=en`、`l=en` 不能保证作者使用英文。保留混合／不确定语言及判断方法；语言修订要精确匹配原文并记录检查者、日期和理由。
3. 观察截止日不等于实际最新评论日。使用香港时间起始日零点到截止日次日零点的半开区间，展示实际观察日期；没有记录不能推断当天没有评论。
4. 1–2 星／3 星／4–5 星是星级情绪代理。主题是规则提及，可含正面、中性或负面；一条可以多主题。不得解释为投诉人数、全部客户的问题发生率、因果或显著性结论。
5. 每批必须实际阅读样本后填写判断；执行者可以是 Codex，但应如实署名为 agent，不冒称独立人工标注。脚本只校验记录格式与样本指纹，不能证明已经阅读，也不提供准确率证书。
6. 每次采集或改变口径／规则使用新批次。不得覆盖历史 raw 响应、拼接旧结论或沿用旧的已检查状态。端点错误／限流按有界策略停止并保存证据，不循环尝试绕过限制。
7. HTML 不内嵌用户名或开发者回复；完整原始数据仍可能含这些字段。只完成用户要求的本地交付，分享、发送、部署和定时执行依用户另行指示。

完成时向用户提供报告、数据表、A–F 文档和验证结果的位置；列出本轮真实条数、窗口、最新日期、采集或导入模式及未完成项。社交媒体、多语言、事件严重性验证、主题逐月趋势和自动报警不属于当前引擎的已实现能力。
