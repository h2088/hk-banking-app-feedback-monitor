# 应用评论监测与竞品对比

默认分析 SC Mobile，HSBC HK 与 BOCHK 作 benchmarks。**英文、中文和中英混合评论共同形成一个分析结果；Google Play 与 Apple App Store 分别计算。** 管理报告与文档使用英文，评论正文和 Apple 标题保留原文。保留 V1 的蓝色横向月度评论量图，显示每家银行的评论数量及低星比例，并随商店切换。

## 识别任务与范围

先看已有配置、checkpoint 和文件，判断是解释、复核、继续批次、新采集还是离线重做。只解释/复核时不自动采集或改结果。用户已指定的对象、窗口和输出位置优先；本项目复跑沿用已确认的 2026-04-19 至 2026-10-19，未来新任务未指定时默认本轮香港日期往前六个日历月，含首尾。不要把历史 1,682 条当成新批次应有结果。

当前 schema-2 引擎支持香港银行领域、一主对象加一至五个 benchmarks、英文/中文共同分析及两家商店分开报告。默认配置含三家银行。其他行业、语言、地区或语言分组是额外适配，不得仅改标签宣称已实现。旧 schema-1 批次与历史 Skill 保留原样；新版写入新批次，不迁移或重写历史验收结果。

- 执行时读 [workflow.md](references/workflow.md) 与 [execution.md](references/execution.md)。
- 导入、清洗、解释分类或填写检查记录时读 [methods.md](references/methods.md)。
- 修改引擎/回归验证时读 [validation.md](references/validation.md)。

入口是 `scripts/run_feedback.py`。按阶段运行：`init` → `collect` 或 `import` → `prepare` → `qa` → `analyze` → 实际阅读样本并填写 `manual_review.json` → `review-status` → `build` → `verify` → `browser-test` → 实际查看截图并填写 `validation/visual_inspection.json` → `finalize`。导入不是新采集，阶段完成由实际文件与检查记录决定。

## 决定结果的方法边界

1. `text` 是客户正文；Apple `title` 分开保留并补充检索/规则匹配。开发者回复不进入分析。不要翻译、润色或转换原始文字。HTML 不嵌入用户名或开发者回复。
2. Google 的 en/zh-HK/zh-CN 是检索参数，不保证作者语言。Apple HK feed 本就可能多语言，不通过多次语言请求制造独立样本。语言只用于纳入与 QA，**不提供语言切换、语言拆分绩效表或语言徽标**，除非用户明确另有要求。
3. 每个指标按银行/商店的全部合格中英文评论计算。不得把英文词典结果当成中文情绪。主体情绪统一是 1–2/3/4–5 星代理；11 类双语主题是可重叠的规则提及，含正面和负面。不能推断投诉人数、真实问题发生率、根因、显著性或全部客户满意度。
4. 用香港时间 `[起始日00:00, 截止日次日00:00)`；实际最新评论日另列。月度图包括窗口内每个月，空月份保留，部分月份明确标注；无记录不证明零反馈。
5. 按平台+应用ID+评论ID去重，保留第一条供给的快照和所有来源引用/不同版本。不同ID的相同文字保留。原始 HTTP 证据、采集时间、请求参数和有界停止原因不可覆盖。失败/限流按有界策略停止。
6. 每个新分析批次实际阅读分层样本后记录逐条判断，agent 如实署名，不冒称独立人工准确率。导入已有语言判断须绑定原文指纹并披露复用；历史个别短句判断不得变成全局白名单。新报告的截图必须实际查看并绑定本次 HTML 哈希。
7. 新采集、日期/规则变更用新批次。若仅修改用户指定的现有展示，先保存可恢复版本并验证原始证据不变；旧的浏览器/视觉通过状态不能沿用。只在本地交付，分享、推送、部署、发送和定时执行需用户另行指示。

完成后提供 HTML、原始总表/Excel、A–F 和验证证据，说明真实条数、窗口、实际最新评论、采集或导入模式及覆盖限制。Skill 包只含方法/代码/模板，不能打包客户评论、原始响应、个人抽查记录或虚拟环境。社交媒体、逐主题月度趋势、真实事件严重性和生产报警未实现。
